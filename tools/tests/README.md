# つみかさねのテスト（tools/tests）

アプリ（`index.html`）を変えたときに、これまでの機能が壊れていないかを自動で確かめる道具です。どのチャットからでも同じように使えます。作業の決まりは [`../WORKFLOW.md`](../WORKFLOW.md) にあります。

## 動かし方

`node`・`python3`・Playwright（Chromium つき）が要ります。クラウドの環境には入っています（`NODE_PATH` は `npm root -g` から自動で見つけます）。

```sh
python3 tools/tests/run.py              # ぜんぶ（比べるテスト＋全スイート、25分ほど）
python3 tools/tests/run.py ToDo         # そのチャットのスイートと比べるテスト（ぜんぶのページのものも）
python3 tools/tests/run.py r37 r38      # 名前を挙げたスイートだけ
python3 tools/tests/run.py cmp          # 比べるテストだけ
python3 tools/tests/run.py --list       # チャットごとのスイートとテストの一覧
```

チャットの名前は `きょう・天気`・`カレンダー`・`ToDo`・`目標`・`つみかさね・記録`・`ダイエット`・`家計簿・バイト`・`日記・勉強・ルーティーン` の8つです。

作業の途中は自分のチャットの分を、出す前には必ずぜんぶを流します。ページどうしは、通知・同期・きょうのタイル・つみかさねのブロックなどでつながっているからです。ぜんぶは時間がかかるので、裏で動かして終わりを待つとよいです（`nohup python3 tools/tests/run.py > /tmp/tests.log 2>&1 &`）。動いている間は、もう1つ `run.py` を動かさないでください（同じサーバーと作業場所を使うため、先のほうが壊れます）。

## 結果の見方

1行に1つのテストの結果が出て、最後にまとめが出ます。新しい失敗（NEW）があれば、終了コードは 1 です。

| 表示 | 意味 |
| --- | --- |
| `OK` | 通った |
| `KNOWN` | そのスイートの `known.txt` にある、前からの失敗。アプリの不具合ではなく、テスト側が古いもの |
| `NEW` | 今回はじめて出た失敗。いまの変更で壊れたかもしれないので直す。変更が意図どおりで、テストの期待のほうが古いときは、テストを直すか、理由を添えて `known.txt` に足す |

- 比べるテスト（`cmp/`）は、同じテストを「変更前」と「今」（作業中のファイル）で動かし、前は通っていて今は落ちるものだけを NEW にします。「変更前」は、ふだんは今のブランチが `origin/main` と分かれたところの `index.html` です（コミットする前でも後でも、自分の変更が入る前のもの）。`BASE=<コミット>` で変えられます。
- ログは `/tmp/tsumikasane-tests/logs/`、まとめは `/tmp/tsumikasane-tests/summary.txt` にあります（場所は `TEST_WORK` で変えられます）。

- テストは `/tmp/tsumikasane-tests/` にコピーしてから動かします。スクリーンショットなどはそちらに出るので、リポジトリは汚れません。
- 例のデータは、どれも 2026年11月ごろの日付です。テストの中で時計を止めています。
- フック版は、どのスイートを動かすときも、ぜんぶ立ち上げます。ほかのスイートのフック版を使うテストもあるからです（たとえば r16・r17・r18・r21 は r19 の 8768 を使います）。
- サーバーは、終わったあとも動いたままです。次に動かすと入れかわります。ほかのもので同じポートがふさがっていると、止まって知らせます。

## スイートのつくり

スイートは `suites/<名前>/` のフォルダー1つです。いくつものチャットが同時にスイートを足してもぶつからないように、1つのスイートのことは、そのフォルダーの中だけに書きます。

```
suites/todo9/
  suite.txt   スイートのこと（下）
  known.txt   前からの失敗（あれば）：「テストのファイル<タブ>失敗の行の一部」を1行ずつ。# の行に理由
  hook.js     フック版を使うときだけ
  lib.js      ブラウザーの用意（phone・seed など）
  data.js     例のデータ
  t1.js …     テスト
```

`suite.txt` の中身（`#` の行は説明で、`--list` に出ます）：

```
# ToDo その12 ①〜⑩
port	8820
chat	ToDo
tests	t1.js t2.js
```

- `port`：フック版のポート（使わないときは `-`）。下のチャットごとの番号帯から、まだ使われていない番号を選びます（`--list` で見られます）。
- `chat`：8つのチャットの名前のどれか。
- `tests`：テストのファイル。この順に動かします。

## テストを足すとき

1. `suites/<名前>/` を作ります。名前は、ページの英字とその回の番号です（例：「ToDo その12」なら `todo12`、「カレンダー その4」なら `cal4`。ほかに `home`・`weather`・`goal`・`tsumi`・`rec`・`diet`・`body`・`money`・`baito`・`journal`・`study`・`routine`）。
2. `lib.js` は `suites/r38/lib.js` をコピーします。例のデータは `data.js`、テストは `t1.js`（`t2.js` …）に書きます。どれも `suites/r38/` が手本です。
3. アプリの中身を使うときは `hook.js` を置きます。1行目に `// insert before: <index.html の中の1行（1か所だけのもの）>` を書き、2行目からに差し込むコードを書きます。手本は `suites/r38/hook.js` です。1行目を書かなければ、起動の行（`// ---------- boot ----------`）の前に入ります。
4. `suite.txt` を書きます（上）。
5. テストは、ぜんぶ通ったら最後に `ALL OK` を、だめなら `FAIL <何が>` の行を出すように書きます（今のテストと同じ書き方）。`Error` を含む行も失敗として数えます。
6. `python3 tools/tests/run.py <名前>` で通ることを確かめます。
